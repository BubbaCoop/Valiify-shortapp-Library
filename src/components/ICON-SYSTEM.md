# Icon System Integration Guide

## There is no icon class

This library ships **no `icon` class and no `icon-size-*` scale**. There is nothing
generic to put on an `<svg>`, and no sizing class family to pick from.

An icon is two things:

1. a `<use>` reference into the sprite, and
2. **the component slot class of wherever it sits** — `.va-toast-icon`,
   `.va-text-field-icon`, and so on — which is what gives it size, colour and stroke.

If you are looking for the class to put on a standalone `<svg>`, see
[Standalone icons](#standalone-icons) — the honest answer is that the paint rules are
not available as a utility yet.

> Until 2026-09 this guide documented an `icon` + `icon-size-*` system in ~39 places.
> That vocabulary came from the dashboard library and never shipped here. It is not a
> rename — the classes never existed in this bundle. `npm run verify:vocabulary` is the
> gate that now holds this document to what `class-manifest.json` actually contains.

## The sprite

`src/icons/sprite.svg` — 2,036 symbols (2,034 [Lucide](https://lucide.dev) + 2 custom),
checked in, `display: none`, generated by `npm run build:icons`.

Reference a symbol by id, with no path and no width/height:

```html
<svg class="va-toast-icon" aria-hidden="true"><use href="#check-circle" /></svg>
```

Lucide symbols keep their upstream kebab-case names (`check-circle`, `alert-triangle`).
The two custom symbols are prefixed: `custom-help`, `custom-valiify-logo`.

## Glyph slot classes

These go **on the `<svg>` itself**. Each applies its own size and colour plus the shared
paint block (`fill: none; stroke: currentColor; stroke-width: 2;` with round caps and
joins), so the markup carries no width, height or styling of its own.

| class | size | colour |
| --- | --- | --- |
| `.va-text-field-icon` | 18px | `text-content-secondary` |
| `.va-action-icon` | 18px | `text-content-secondary` |
| `.va-toast-icon` | 18px | inherited from the toast variant |
| `.va-text-selector-icon` | 16px | `text-neutral-disabled` |

```html
<div class="va-text-field-box">
  <svg class="va-text-field-icon" aria-hidden="true"><use href="#search" /></svg>
  <input class="va-text-field-input" type="text" />
</div>
```

## Icon buttons

A different family: these go on the **`<button>`**, not the `<svg>`, and size the child
glyph for you. The button is transparent and borderless — the glyph is the box.

| class | box | notes |
| --- | --- | --- |
| `.va-icon-button` | 18px | base; `text-neutral` |
| `.va-icon-button-sm` | 14px | size modifier, also resizes the child `svg` |
| `.va-icon-button-subtle` | — | colour modifier: starts `text-neutral-disabled`, darkens on hover |
| `.va-icon-button-state` | 24px | adds 3px padding around the 18px glyph; combined with the `sm` modifier it is an 18px box around a 14px glyph |

```html
<button class="va-icon-button va-icon-button-subtle" aria-label="Dismiss">
  <svg aria-hidden="true"><use href="#x" /></svg>
</button>
```

The inner `<svg>` takes **no class** — the button sizes it.

## Standalone icons

For an icon outside any component slot, size and colour are available as utilities but
**the paint block is not**:

- **Size** — the whole scale is `va:size-3.5`, `va:size-4`, `va:size-4.5`, `va:size-5`,
  `va:size-8.5` (14, 16, 18, 20, 34px). There is nothing else; these are the sizes the
  Figma frames actually use.
- **Colour** — any `va:text-*` token utility, e.g. `va:text-content-secondary`.
- **Stroke and fill** — no utility ships for this. Lucide symbols carry no fill and rely
  on `fill: none; stroke: currentColor; stroke-width: 2`, which today exists only inside
  the glyph slot classes above.

So a standalone icon either sits inside one of those slots, or its paint is written by
hand. The repository's CLAUDE.md tracks the fix — folding the repeated paint block into one
`@utility icon-glyph` — as a deliberate, deferred refactor needing full visual
re-verification. Until it lands, **prefer a slot class over a bare `<svg>`.**

## Accessibility

| case | markup |
| --- | --- |
| Decorative (most icons — the label is adjacent text) | `aria-hidden="true"` on the `<svg>` |
| Icon-only control | `aria-label` on the **button**, `aria-hidden="true"` on the `<svg>` |
| The icon itself carries meaning | give it `role="img"` and a `<title>` child |

```html
<svg role="img"><title>Verified</title><use href="#shield-check" /></svg>
```

## Adding a custom icon

```sh
cp my-glyph.svg src/icons/custom/   # 24×24 viewBox, stroke-based, no fill
npm run build:icons                 # regenerates src/icons/sprite.svg
```

It becomes `#custom-my-glyph`. The sprite is a pure function of its sources and carries
no build timestamp, so rebuilding without changing an icon produces no diff.
